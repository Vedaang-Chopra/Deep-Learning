## Mechanics
- **Model:** five `prof` values, starting at 0.22–0.38. Each task's hidden unknown is one scale; demand = scale × shape.
- **Group value:** expected spread = (7/8)·p(1−p), so expected credit per group is 0.21·p(1−p). Best at p≈0.5; p in 0.2–0.8 keeps ≥64% of that.
- **Target task:** single-skill p≈0.5 at demand ≈ prof + 0.49, so the frontier moves as skill grows.
- **Diminishing returns:** gain scales with `(1 − prof)`, so a nearly mastered skill is poor value.
- **Bank layout:** four zones: solved, live, later, unreachable. Roughly 10/12/40/38% before jitter, with scale up to 2.6. Layout and starting prof are redrawn per run.
- **Eval:** probes sit around scale 0.45–1.30, plus up to 0.08. Hard probes need near-mastery in every required skill.

## Insights that shape design
1. **Budget isn't the main limit.** The ceiling is ~38 credit units (720 × 0.0525), and ~2–3 per skill already gives prof ≈ 0.9. The limit is finding tasks near p≈0.5 as prof rises.
2. **Prof is nearly observable.** Credit is computed from k, which I see. So prof = unknown start + known deltas, and each task needs only a scale estimate. A grid posterior per task looks cheap and accurate.
3. **No per-task limit or overfitting.** Repeating one good task per skill is valid. Coverage matters only through skills.
4. **Balance is the hedge.** Eval mix differs from train, and pass is conjunctive. Reasoning appears in only 13 of 120 tasks, mostly paired, so a greedy scheduler would starve it.
5. **Probes aren't wasted.** Pending groups persist, so a probe rollout counts toward that task's group. A group flushed at the end still banks (size−1)/size efficiency, and only a singleton is worthless.
6. **Poison shows up as a mismatch.** Observed pass rates fall below the prediction from assumed-positive credit. Updates land every 60 rollouts, so attribution needs care. Single-skill tasks are the cleanest evidence. Test "does this bank have poison at all?" first, so clean banks pay little.

- Each task counts its own attempts.
- At 8 attempts, the group closes and the simulator looks at the mix of passes and fails.

- Only now does the model actually improve.

**Example**

- Attempts 9–16 on task B: 8 pass. Nothing is stored.

**Why it matters**

- Between updates, skills stay frozen, so pass chances don't change during those 60 attempts.
- Only full, mixed groups store real learning, so half-finished groups give nothing until they close. Any group still open when the budget ends is closed then, but counts for less.

At each step, pick by asking three questions in order. This is my suggested rule, and we still need to test it.

**1. Is a group already open on a useful task?**
- If yes, keep going until it reaches 8.
- If its results so far suggest it won't teach much, drop it for now.

**2. Which skill is weakest right now?**
- Use your estimated skill levels, since the true ones are hidden.
- Weak skills are the best value: gain scales with `1 − skill`, and the exam can test any skill.

**3. Which task for that skill is closest to 50% pass?**
- Look at tasks where that skill is the main one (`1.0`).
- Use each task's pass history to estimate its pass rate.
- Pick the one closest to 50%.
- If none look useful, move to the next weakest skill.

**The same rule as one formula**

Score every task and pick the highest:

```text
score = p × (1 − p) × (sum over the task's skills of: share × (1 − skill))
```

- `p × (1 − p)`: how mixed its results will likely be, which is highest at 50%.
- `share`: how much of the learning goes to that skill.
- `1 − skill`: how much room that skill has left to grow.

**Example**

| Task | Skill | Pass chance | Skill level | Score |
|---|---|---|---|---|
| A | Coding | 50% | 0.9 | 0.25 × 0.1 = 0.025 |
| B | Reasoning | 30% | 0.4 | 0.21 × 0.6 = 0.126 |
| C | Math | 50% | 0.6 | 0.25 × 0.4 = 0.100 |

Pick **B**. It has a worse pass chance than A, but reasoning has far more room to grow.

**Hard part**
- `p` and `skill` are estimates built from pass/fail history. Building those estimates is the main work of the scheduler, so that's the next thing to design.
