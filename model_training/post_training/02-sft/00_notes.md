# Supervised Fine Tuning 

You are mostly correct, but there are two distinctions.
- Supervised Fine-Tuning (SFT): A general technique for training a pretrained model on labeled input-output examples using supervised learning.
- Instruction Fine-Tuning (IFT): A specific type of SFT where the model learns from instruction-response pairs.
- Relationship: Instruction Fine-Tuning ⊂ SFT. All instruction fine-tuning is SFT, but not all SFT is instruction fine-tuning.
- Mid-training: Not the same as SFT. Mid-training typically refers to continued pretraining on specialized data, between general pretraining and post-training.
Example:
- Pretraining → Learn language through next-token prediction.
- Mid-training → Continue pretraining on domain-specific text.
- SFT → Fine-tune on labeled examples.
- Instruction Fine-Tuning → SFT specifically on instruction-response examples.
Key takeaway: In LLM post-training, people often use SFT and instruction tuning interchangeably because instruction tuning is a common application of SFT.




SFT is an umbrella term. Instruction fine-tuning is one application of it.
Common forms of SFT
Type	What the model learns
1. Instruction Fine-Tuning	Follow instructions and produce appropriate responses
2. Task-Specific Fine-Tuning	Perform a particular task, such as classification, translation, or summarization
3. Domain-Specific SFT	Perform supervised tasks using medical, legal, or financial knowledge
4. Conversational Fine-Tuning	Handle multi-turn conversations and dialogue context
5. Reasoning Fine-Tuning	Generate solutions, sometimes with step-by-step reasoning traces
6. Tool-Use Fine-Tuning	Select tools, generate function calls, and interpret tool outputs
7. Safety Fine-Tuning	Follow safety policies, handle harmful requests, and produce appropriate refusals
8. Distillation-Based SFT	Learn from responses or demonstrations generated by a stronger teacher model
How does mid-training differ?
	Mid-training	SFT
Typical data	Domain-specific raw text	Labeled input-output examples
Objective	Usually continued next-token prediction	Supervised target prediction, often next-token loss on responses
Purpose	Improve knowledge and domain adaptation	Teach desired tasks and behaviors
Important distinction
- These SFT categories overlap. They are not separate optimization algorithms.
- Instruction tuning can simultaneously teach reasoning, tool use, and safety.
- The main difference is the training data and target behavior, not necessarily the loss function.
Mental model: Pretraining → optional mid-training → SFT (instruction, reasoning, tool use, etc.) → preference optimization / RL.

## 2. Loss masking deserves special attention

Assume the input is:

`User: What is 2+2? Assistant: 4`

| Masking strategy  | Tokens contributing to loss           |
| ----------------- | ------------------------------------- |
| Full-sequence     | User + Assistant                      |
| Completion-only   | Only the target completion (`4`)      |
| Assistant-only    | All assistant turns in a conversation |
| Last-turn-only    | Only the final assistant response     |
| Selective masking | Specific response segments or tokens  |

Important: The prompt still enters the model. Masking determines which tokens contribute to the loss, not which tokens the model can read.

Also learn the distinction between `attention_mask` and `labels=-100`.

## 3. Separate SFT from model adaptation

These are independent choices:

- Full fine-tuning: Update all model parameters.
- LoRA: Update low-rank adapters.
- QLoRA: Train adapters with a quantized base model.

You can use any of these with instruction SFT.

| Format            | Structure                                        | Use                                        |

- ChatML: `<|im_start|>user ...`
- Llama 3: `<|start_header_id|>user ...`

## 2. Different loss masking strategies

| Strategy             | Which tokens contribute to loss?                                 |
| -------------------- | ---------------------------------------------------------------- |
| Full-sequence loss   | All eligible tokens: system, user, assistant                     |
| Completion-only loss | Only tokens in the completion field                              |
| Assistant-only loss  | Assistant messages across conversation turns                     |
| Last-turn-only loss  | Only the final assistant response                                |
| Selective masking    | Specific tokens or segments, such as tool calls or final answers |

In SFT, formats define how training examples are structured and represented. They do not define different training algorithms.

There are two levels to understand:

1. Dataset formats — How instructions and responses are stored.
2. Chat templates — How that data is converted into the token sequence the model sees.

## 1. Common SFT dataset formats

| Format            | Structure                                        | Primary use                      |
| ----------------- | ------------------------------------------------ | -------------------------------- |
| Alpaca            | `instruction`, `input`, `output`                 | Single-turn instruction tuning   |
| ShareGPT          | `conversations` with `human`, `gpt` roles        | Multi-turn conversations         |
| OpenAI Messages   | `messages` with `role`, `content`                | Chat, multi-turn, tool use       |
| Prompt-Completion | `prompt`, `completion`                           | General supervised training      |
| FLAN-style        | Task instruction, input, target                  | Multi-task instruction tuning    |
| Dolly-style       | `instruction`, `context`, `response`, `category` | Categorized instruction datasets |

## 2. What do these formats look like?

Alpaca

```
{
  "instruction": "Translate to French",
  "input": "Hello",
  "output": "Bonjour"
}
```

ShareGPT

```
{
  "conversations": [
    {"from": "human", "value": "Hello"},
    {"from": "gpt", "value": "Hi!"},
    {"from": "human", "value": "Translate hello to French"},
    {"from": "gpt", "value": "Bonjour"}
  ]
}
```

OpenAI Messages

```
{
  "messages": [
    {"role": "system", "content": "You are a translator."},
    {"role": "user", "content": "Translate hello to French"},
    {"role": "assistant", "content": "Bonjour"}
  ]
}
```

## 3. Why do different formats exist?

- Historical reasons: Different research groups and datasets adopted different schemas.
- Task complexity: Alpaca works for simple instruction-response pairs; ShareGPT represents conversational history.
- Role information: Messages formats explicitly represent system, user, assistant, and tool messages.
- Training flexibility: Prompt-completion separates conditioning context from the supervised target.

Important: The same conversation can often be represented in multiple formats without changing its meaning.

## 4. Dataset format vs chat template

A dataset might store:

`{"role": "user", "content": "Hello"}`

But the model may receive different token sequences depending on its chat template.

| Chat template    | Example representation                      |
| ---------------- | ------------------------------------------- |
| ChatML           | `<\\|im_start\\|>user`                      |
| Llama 3          | `<\\|start_header_id\\|>user<\\|eot_id\\|>` |
| Mistral Instruct | `[INST] Hello [/INST]`                      |

These special-token representations are separate from dataset schemas.

## 5. What you should understand first

- Alpaca: Understand basic instruction-response training.
- ShareGPT / Messages: Understand multi-turn conversations and roles.
- Chat templates: Understand how structured data becomes model input tokens.
- Loss masking: Understand which tokens contribute to cross-entropy loss.

Key takeaway: Different formats organize training data differently. The underlying SFT process remains largely the same. The format itself does not determine the loss masking strategy.
